    Function hasBlockedAncestor

    • hasBlockedAncestor(el: Element | null): boolean

      Returns true if el (or any ancestor, inclusive of el itself) has a tag name in BLOCKED_TAGS or matches WIDGET_SELECTOR.

      Implemented with the native Element.closest() against pre-joined selectors rather than a hand-rolled while (cursor) { cursor = cursor.parentElement } loop. closest() is implemented natively in the browser and is substantially faster than walking the ancestor chain in JS one tag-name comparison at a time — this function runs once per candidate element across every feature in this file, so on large pages the difference is real, measurable latency rather than a micro-optimization.

      closest() starts its match check at el itself, not at its parent — callers must pass the actual element they're deciding about, not el.parentElement. An earlier version of collectBlockElements passed el.parentElement here, which meant a block element that was itself widget-classed — e.g. a .CarouselSlide-info-content div, a .ReadMore toggle, a caption <p> — slipped through whenever its immediate parent happened not to repeat that class. That's what let reading-tool features reach into AP News's photo/video carousel markup and corrupt it. collectBlockElements now correctly passes el itself.

      Exported (not just used internally) so that features which build their own bespoke traversal inside an already-selected Pattern B block — sentenceSplitter.ts's buildNormMap, for instance, which walks with a raw TreeWalker rather than going through walkTextNodes — can apply the same per-text-node exclusion that walkTextNodes gets for free. Without that, a block-level check that lets a container through (or that a nested-candidate/dedup edge case slips past) leaves every text node inside it, including nested widget fragments, completely unfiltered during that custom walk.

      Parameters

      • el: Element | null

        Element to test (checked inclusively, then its ancestors).

      Returns boolean
