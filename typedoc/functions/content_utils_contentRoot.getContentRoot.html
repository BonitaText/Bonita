    Function getContentRoot

    • getContentRoot(): Element

      Resolves the best-guess content root for the current page.

      Tries semantic/landmark selectors in priority order, but — unlike the naive version every feature used to implement independently — validates each candidate against MIN_ROOT_CHARS before accepting it. A selector match that resolves to a small, unrelated element (a sidebar widget, a single ad slot, an empty landmark) is rejected and the search continues, falling back to document.body if nothing qualifies.

      The result is cached across calls within the same page — resolving the root re-runs querySelector and a textContent length check per candidate selector, and this is called by nearly every reading-tool feature on every analysis pass, so re-resolving from scratch each time was pure waste on pages where the DOM isn't changing shape between calls.

      Landmark entries are validated with document.contains() on every read, so the cache self-invalidates if the cached element gets removed (e.g. an SPA route change tears down and rebuilds the root). A landmark entry is otherwise returned as-is: a higher-priority landmark appearing later does not displace it.

      The <body> fallback is cached too, but revalidated. document.body is never detached, so document.contains() can never invalidate it; a fallback resolved before the article has rendered (SPA navigation, lazy hydration) would otherwise stick forever and every feature would run against <body> instead of the article. While the fallback is cached, a MutationObserver records whether the DOM has changed in a way that could produce a landmark (see watchForLandmarks). On each call:

      1. pending mutation records are drained synchronously with takeRecords() (so same-tick changes are seen immediately);
      2. if nothing changed since the fallback was last confirmed, the cached <body> is returned with zero DOM queries;
      3. if something changed, a single combined querySelector (ROOT_PROBE) checks whether any landmark candidate exists at all — if none, the cached <body> is still correct and returned; otherwise the full resolution below runs.

      The observer only runs while the fallback is cached and is disconnected as soon as a real landmark resolves, so well-structured pages pay nothing for it.

      Call invalidateContentRootCache explicitly before a fresh analysis pass if you know the page content changed but the old root element is still attached (e.g. its content was replaced in place) — the document.contains() self-check only catches the case where the old root was removed entirely.

      This is the single point of truth for "where is the article" — every feature should call this (or accept an explicit root override) rather than maintaining its own selector list.

      Returns Element

      The resolved root element. Always returns something — document.body in the worst case — so callers never need to null-check.
